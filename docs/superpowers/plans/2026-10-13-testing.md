# Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add unit, config, component and E2E tests, a coverage report and CI to the Redoc partner docs app, so a hidden endpoint can never leak into a partner's page unnoticed.

**Architecture:** Vitest runs two projects (`unit` in Node, `component` in jsdom). Playwright runs against a production build on port 3100. Unit tests of `filterSpec` use a small fixture; the config-validity and E2E tests use the real `partners/` and `specs/` files. GitHub Actions runs lint, coverage and E2E.

**Tech Stack:** Vitest, `@vitest/coverage-v8`, `vite-tsconfig-paths`, `@vitejs/plugin-react`, jsdom, Testing Library, Playwright (Chromium), Next.js 16.4.0, Node 24.

**Spec:** `docs/superpowers/specs/2026-10-13-testing-design.md`

## Global Constraints

- Test files sit next to the source: `<name>.test.ts` / `<name>.test.tsx`. Playwright files use `.spec.ts` under `tests/e2e/`.
- One top-level `describe` per module, named after it. Titles are plain sentences starting with a verb; no "should", no function names.
- Arrange, act and assert are separated by blank lines. No inline styles (CSS Modules only).
- Tests are deterministic and independent: no network, no clock, no shared mutable state. Clone fixtures per test with `structuredClone`.
- Mock only what the project does not own (`node:fs`, `redoc`), never its own functions.
- Playwright: Chromium only, port 3100, `localhost` (never `127.0.0.1`).
- Coverage measures `lib/**` only, with no thresholds.
- Commit messages: Conventional Commits with an allowed type (`feat`, `fix`, `docs`, `refactor`, `chore`, `style`, `test`), imperative, 72 characters or fewer, no `Co-Authored-By` trailer. Test files use `test:`; config, coverage and CI use `chore:`; bug fixes found by tests use `fix:`.
- Before writing a test, check existing tests for the same behavior and extend them instead of duplicating.
- Next.js here differs from older versions; consult `node_modules/next/dist/docs/` before changing Next-specific code.

## Review Focus

- Partner name ending in a non-word character (`Acme (EU)`): the title check in `filterSpec` uses `\b`, so it may add a second prefix. Expected: no double prefix. Pinned in Task 2.
- `include.tags` that matches no tag in the spec: expected an empty `paths` and pruned `components`, no throw. Pinned in Task 1.
- Spec with no `info`, `components` or `paths` (webhooks only): expected no throw. Pinned in Task 2.
- Cyclic `$ref`s (Pet to Category to Pet): expected pruning terminates and keeps both. Pinned in Task 3.
- Slug variants for the loaders (`../partners/acme`, `acme/../globex`, `ACME`, empty string, `acme.json`): expected `null`. Pinned in Task 4.

### Task 1: Vitest setup and `filterSpec` operation filtering

**Files:**
- Create: `vitest.config.ts`, `lib/__fixtures__/spec.json`, `lib/__fixtures__/partner.json`, `lib/filterSpec.test.ts`
- Modify: `package.json`

**Interfaces:**
- Produces: `npm test` and `npm run test:watch`; the Vitest projects `unit` and `component` (the latter has no files yet); the two fixtures every `filterSpec` test builds on.

- [ ] **Step 1: Install and configure Vitest**

Run `npm install -D vitest @vitest/coverage-v8 vite-tsconfig-paths @vitejs/plugin-react jsdom @testing-library/react @testing-library/dom`. Check the installed Vitest version's docs in `node_modules/vitest` for the `test.projects` syntax, then create `vitest.config.ts` with shared plugins `[tsconfigPaths(), react()]` and two projects (both `extends: true`):
- `unit`: `environment: "node"`, `include: ["lib/**/*.test.ts", "tests/**/*.test.ts"]`
- `component`: `environment: "jsdom"`, `include: ["components/**/*.test.tsx"]`, `passWithNoTests: true` if the version requires it for an empty project.

Add scripts `"test": "vitest run"` and `"test:watch": "vitest"`.

- [ ] **Step 2: Write the fixtures**

`lib/__fixtures__/spec.json` (OpenAPI 3.0.4, `info.title` "Fixture API", `servers` `[{ "url": "https://original.example" }]`):
- `tags`: `pets`, `admin`, `billing`; `x-tagGroups`: `Core` (`pets`, `admin`) and `Money` (`billing`).
- `paths`: `/pets` (get `listPets` [pets]; post `createPet` [pets, admin]), `/pets/{petId}` (get `getPet` [pets]; delete `deletePet` [pets]), `/internal/stats` (get `stats` [pets], `x-internal: true`), `/admin/users` (get `listUsers` [admin]), `/invoices` (get `listInvoices` [billing]).
- `webhooks`: `petAdded` (post `onPetAdded` [pets]) and `adminAlert` (post `onAdminAlert` [admin]).
- `components.schemas`: `Pet` (properties `category` -> `Category`, `owner` -> `#/components/schemas/Pet%20Owner`, `shape` -> `Shape`), `Category` (property `parent` -> `Pet`, forming a cycle), `Pet Owner`, `Shape` (a `discriminator.mapping` of `circle` -> `#/components/schemas/Circle`), `Circle`, `User`, `Invoice`, `StatsOnly`, `Unused`, `PetEvent` (request body of `onPetAdded` only) and `AdminEvent` (request body of `onAdminAlert` only).
- Each operation's 200 response references the schema its name implies (`listPets`/`getPet` -> `Pet`, `listUsers` -> `User`, `listInvoices` -> `Invoice`, `stats` -> `StatsOnly`).
- `components.securitySchemes.api_key` (never referenced by `$ref`).

`lib/__fixtures__/partner.json`: `name` "Fixture Partner", `spec` "spec", `logo` "https://example.com/logo.png", `servers` `["https://partner.example/v1"]`, `include.tags` `["pets"]`, `exclude.operationIds` `["deletePet"]`.

- [ ] **Step 3: Write the failing tests**

In `lib/filterSpec.test.ts`, `describe("filterSpec")` with a nested `describe("operation filtering")`. Import both fixtures and call `filterSpec(structuredClone(spec), { ...partner, ...overrides })`. Tests:
- `it("drops operations without an allowed tag")`: no `/admin/users` or `/invoices` in `paths`.
- `it("strips non-allowed tags from kept operations")`: `paths["/pets"].post.tags` equals `["pets"]`.
- `it("keeps every operation when include.tags is empty")` and `it("keeps every operation when include is missing")`: every path except `/internal/stats` remains.
- `it("drops x-internal operations")`: no `/internal/stats`.
- `it("drops excluded operationIds")`: `/pets/{petId}` has `get` but no `delete`.
- `it("removes a route once none of its methods remain")`: with `exclude.operationIds` `["getPet", "deletePet"]`, no `/pets/{petId}` key.
- `it("filters webhooks like paths")`: `webhooks.petAdded` kept, `webhooks.adminAlert` removed.
- `it("returns empty paths and components when no tag matches")` (Review Focus): `include.tags` `["nope"]` gives `paths` equal to `{}`, no schemas, and does not throw.

- [ ] **Step 4: Run and verify**

Run: `npx vitest run lib/filterSpec.test.ts`
Expected: all PASS (the code already exists). If a test fails, decide whether the test or `filterSpec` is wrong; fix code bugs in a separate `fix:` commit.

- [ ] **Step 5: Confirm a test can fail**

Temporarily delete the `x-internal` check in `lib/filterSpec.ts`, run the file, see `drops x-internal operations` fail, then restore the line.

- [ ] **Step 6: Commit**

```bash
git add vitest.config.ts package.json package-lock.json lib/__fixtures__ lib/filterSpec.test.ts
git commit -m "test: add Vitest setup and filterSpec operation tests"
```
